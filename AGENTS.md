# AGENTS.md

Guidance for coding agents working in this repo.

## What this is

`kdn` is a small Rust CLI that drives a locally running Kaiden desktop app through its HTTP/WebSocket API on `127.0.0.1`. See `README.md` for user-facing usage.

## Layout

- `src/main.rs` — clap definitions (`Cli`, `Commands`, `WorkspaceCommands`) and dispatch. Reads the endpoint once via `config::api_endpoint()`.
- `src/config.rs` — finds Kaiden's `api-port` file (port + bearer token) and has `encode()` for URL percent-encoding.
- `src/commands/` — one file per subcommand: `list.rs`, `delete.rs`, `terminal.rs`, `agent.rs`. `agent.rs` is a thin wrapper over `terminal::run_terminal`.

## Build, test, lint

```sh
make build
make test
make lint    # cargo fmt --check && cargo clippy --all-targets --locked -- -D warnings
```

All three must pass before you consider a change done. `make ci-checks` (lint + test) is what `.github/workflows/pr-checks.yml` runs on Linux and macOS. That workflow also runs `cargo deny check` (`deny.toml`: advisories, licenses, sources); run it locally with `cargo install cargo-deny --locked && cargo deny check` when you touch dependencies.

Lint policy lives in `[lints]` in `Cargo.toml`: clippy `pedantic` is on and `unsafe_code` is forbidden. Fix warnings rather than adding `#[allow]`.

## Conventions

- Rust 2024 edition, no async runtime. I/O is blocking: `ureq` for HTTP, `tungstenite` for WebSocket.
- Unix only. Terminal raw mode and window size go through `rustix::termios` (safe wrappers; no `unsafe` in the crate).
- Errors are `Result<_, Box<dyn std::error::Error>>` surfaced by `main`; build messages with `format!(..).into()` or `"text".into()`. Keep user-facing messages short and actionable (see `config::api_endpoint` for the tone).
- Every source file starts with the `Copyright (C) 2026 Red Hat, Inc.` and `SPDX-License-Identifier: Apache-2.0` header. Copy it into new files.
- Prefer stdlib over a new dependency. Do not add crates for things a few lines cover.
- Unit tests live inline under `#[cfg(test)] mod tests` next to the code (see `src/config.rs`). There is no `tests/` directory.

## Adding a subcommand

1. Add a variant to `WorkspaceCommands` in `src/main.rs` and a match arm in `main`.
2. Create `src/commands/<name>.rs` with a `pub fn run(...) -> Result<(), String>`.
3. Register the module in `src/commands/mod.rs`.
4. Document it in `README.md`.

## CI and releases

- `.github/workflows/pr-checks.yml` — lint, test, build on `ubuntu-24.04` and `macos-26` for every PR. Docs-only PRs skip it.
- `.github/workflows/release.yml` — **generated by cargo-dist**. Do not hand-edit; change `dist-workspace.toml` and run `dist generate`. Its GitHub Actions are pinned to commit SHAs through `[dist.github-action-commits]` in `dist-workspace.toml`; dependabot ignores those three actions (`checkout`, `upload-artifact`, `download-artifact`), so bump them by hand in `dist-workspace.toml` and in the other two workflows together, then run `dist generate`.
- `.github/workflows/bump-next-version.yml` — called after a release; opens an auto-merge PR setting `Cargo.toml` to the next minor with a `-next` suffix. Needs the `KAIDEN_BOT_TOKEN` secret.
- `.github/dependabot.yml` — daily cargo and github-actions updates (minus the three actions owned by cargo-dist, see above).
- `.github/PULL_REQUEST_TEMPLATE.md`, `.github/ISSUE_TEMPLATE/` — PR checklist and issue forms. `CONTRIBUTING.md` is the human-facing version of this file.

To release: set `version` in `Cargo.toml` to `X.Y.Z` (drop `-next`), commit, then `git tag vX.Y.Z && git push origin vX.Y.Z`. The tag must match the Cargo version.

## Don'ts

- Don't commit `target/`.
- Don't change the `api-port` lookup order or the `127.0.0.1` binding without a reason; Kaiden owns that contract.
